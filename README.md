# NETRA

Privacy-preserving on-device visual perception prototype — SIH 2026, PS ID 26171, Team Rakshak.

Upload an image → detect sensitive regions on-device (faces, PII text) → render a redacted
(Set-of-Mark) output image. Everything runs client-side, in the browser, with no server-side
component.

This file covers practical setup, running, and testing. For project rules, file ownership, and
technical decisions, see [`CLAUDE.md`](CLAUDE.md). For the `Detection` data shape both modules
depend on, see [`docs/interface-contract.md`](docs/interface-contract.md).

## Setup

Run these in order — steps 3–5 generate build output that isn't checked into git
(`models/ort-wasm/`, `models/tesseract/`, and `dist/` are all gitignored), so skipping any of
them leaves the extension unable to load.

```bash
# 1. Clone and enter the repo
git clone <repo-url>
cd Netra

# 2. Install dependencies
npm install

# 3. Vendor the ONNX Runtime Web wasm assets (face detection)
npm run build:wasm

# 4. Vendor the Tesseract.js worker/core/language assets (OCR)
npm run build:tesseract

# 5. Bundle the popup script
npm run build:popup
```

Step 5 is required and easy to miss: `src/ui/popup.html` loads `dist/popup.bundle.js`, which only
exists after this command runs. Without it, the popup fails to load at all.

(Steps 3–5 together: `npm run build`.)

6. Load the extension, in any Chromium-based browser (Chrome, Edge, and Brave are all confirmed
   working):
   - Go to `chrome://extensions` (or `edge://extensions`, `brave://extensions`)
   - Enable **Developer mode** (top-right)
   - Click **Load unpacked** and select this repo's root folder

### Rebuilding after code changes

`dist/popup.bundle.js` is a build artifact, not a live file — the browser doesn't see edits to
`src/ui/popup.js` or anything under `src/detection`/`src/redaction` until you rebuild it:

```bash
npm run build:popup
```

Then reload the extension from `chrome://extensions` (click the reload icon on its card).

Pass `--watch` to rebuild automatically on file changes during a dev session:

```bash
node scripts/build-popup.mjs --watch
```

(`models/ort-wasm/` and `models/tesseract/` don't need regenerating unless you reinstall
`node_modules` or bump the `onnxruntime-web`/`tesseract.js` versions — rerun steps 3–4 if so.)

## Run tests

```bash
npm test
```

`npm test` needs Node 18+ (a Vitest requirement). On a machine stuck on an older Node, `bun test`
runs the identical suite and is an accepted equivalent for this project.

## Known limitations

**Masked password/PIN fields (dot- or asterisk-style, e.g. `••••••••`) are not detected.** This
is a deliberate, accepted scope decision, not a bug to fix. Root cause: Tesseract's OCR layout
analysis and glyph recognition can't reliably handle mask characters — in testing, a
bullet-masked field was transcribed as the literal letters `"sssssssss"` (not matched by anything
a password-mask regex could reasonably catch), and an asterisk-masked field wasn't segmented as a
text line at all, so it never reached the PII classifier as a candidate word. Loosening the
matcher to catch one observed OCR misreading would just overfit to that specific font/glyph
without producing a real fix. See `src/detection/piiClassifier.js`'s file header for the full
observed failure modes.

## Project layout

- `src/detection/` — Person 1: face/text/PII detection, exposes `detectSensitiveRegions(image)`
- `src/redaction/` — Person 2: Set-of-Mark + blur/mask rendering, exposes
  `renderRedactedImage(image, detections)`
- `src/ui/` — Person 2: extension popup (`popup.html`/`popup.js`/`popup.css`)
- `src/shared/` — shared contract (`types.js`) and image helpers (`imageUtils.js`)
- `src/mock/` — fake detection data for UI development independent of the real detector
- `models/` — ONNX model weights (Person 1); `models/ort-wasm/` and `models/tesseract/` are
  generated by `npm run build:wasm` / `npm run build:tesseract` (gitignored)
- `scripts/` — build and dev-smoke-test scripts, including `build-popup.mjs` (the popup bundler)
- `dist/` — generated by `scripts/build-popup.mjs` (gitignored); what the extension actually loads
- `docs/interface-contract.md` — the frozen `Detection` shape both modules rely on
- `docs/session-log/` — historical planning/handoff docs from earlier in development; not
  referenced by any code, kept as a record rather than deleted
